<h1 align="center"> JHotReload </h1>

<strong>JHotReload</strong> is a Java library that can be used to quickly change variable values at runtime without the need to re-compile and re-run the program over and over again, everything is done through JSON files!

- Disclaimer: Yes, I know this is not real Hot Reload, in fact, this is not a Hot Reload library, it's a JHot Reload library! (does 'J' stand for JSON or Java? I dunno)


<h2 align="center">Intended purpose</h2>

You could include this library in your Java projects and then use it directly through its API (see <a href="#htui"><b>How to use it? (via API)</b></a>), but its intended use is to be implemented in development environments (IntelliJ, Eclipse, VS Code, etc.) as a plugin to manage it easily (you still need to know how to use its <a href="#htui"><b>API</b></a> to do so obviously), there are two main reasons:

<ul>
    <li>Dealing with JSON files can be annoying, it would be much better to use GUI's</li>
    <li>Final builds don't include files generated by JHotReload during development, they need to be baked in the JAR through gradle (or equivalent), with a plugin that can be done automatically for every project, a plugin can also automatically disable JHotReload in its config file when building the project, see <a href="#baking"><b>File baking</b></a></li>
</ul>

<h2 align="center" id="htui">How to use it? (via API)</h2>

After importing the library in your Java project, you can use it via its API.

First include the needed imports:<br>
<code>import net.jhotreload.components.variables.HotVariable;</code><br>
<code>import net.jhotreload.components.variables.JVariable;</code>

The only thing you need to do now is declare the variable you want to modify at runtime as a Hot Variable:

<code>JVariable&lt;Type&gt; name = HotVariable.of(value, "name");</code>

or (you only need the first import in this case):

<code>var name = HotVariable.of(value, "name");</code>

Of course, only manually editable types are supported.<br>
Supported types:<br>
<code>Integer</code><br>
<code>Float</code><br>
<code>Double</code><br>
<code>Boolean</code><br>
<code>Character</code><br>
<code>String</code>

<b>WARNING: Two or more Hot Variables cannot share the same name (the one assigned in the constructor) if they are in the same class. In that case, if they are of the same type the one declared last will overwrite the others, else you'll get an error.</b>

Now you can use your variable in code normally with:<br>
<code>name.set(newValue);</code><br>
<code>name.get();</code>

<h4 align=center>JHot reloading</h4>

Now that you have declared a Hot Variable, you can get to the part where you change its value manually at runtime (make sure that the code instantiating the Hot Variable is executed at least once before performing the following steps):

<ol>
    <li>Go to your project's root directory</li>
    <li>Open the directory named <code>JHotReload</code></li>
    <li>There you'll find JSON files containing the values ​​for each Hot Variable, organized in a folder structure that mirrors your project's package structure</li>
    <li>Find and open the JSON file named after the class where you declared the Hot Variable whose value you want to change</li>
    <li>The file will contain all the Hot Variables declared in that class in this format:<br> <code>name : value</code><br>
    change the value to whatever you want and watch it update in real-time in your running program as well</li>
</ol>

Don't worry about accidentally entering invalid values in the JSON file, if you do, the last valid one will be used instead until you enter a new valid one.

Note that changes are permanent, so when the program is restarted Hot Variables will no longer use the value they were declared with, they'll read directly the one from the JSON file.

Remember that <code>hotVariable.set(newValue)</code> also changes the value in the JSON file.


<br>
Also, JHotReload is only supposed to be used for testing different values, when you're not doing that, or when you're building the release of your software, you should disable it to prevent various issues (you will not lose the values you set in the JSON files).
<br>
See <b><a href="#config">Config</a></b>.

<h2 align="center" id="config">Config</h2>
When JHotReload is initialized (this happens the first time your code runs a Hot Variable declaration) it generates a config file in <code>JHotReload/@CONFIGJHotReload.json</code>.
<br><br>
The config file contains two properties:
<br>
<code>isJHotReloadActive</code>
<br>
<code>crashOnJReadWriteFailure</code>

<br><br>

<h4 align="center"><code>isJHotReloadActive</code></h4>

<br>

<code><i>default value: true</i></code>

<br>

This property is very important; it's used to turn on/off variable reloading.

When it's set to true, Hot Variables behave as discussed in the <b><a href="#htui">How to use it? (via API)</a></b> section.

But there are two major issues with keeping this behaviour on outside of testing:

<ul>
    <li>Performance: constant reading and writing to JSON files is not good for performance</li>
    <li>Shared values behaviour: since Hot Variables get their value from JSON files, different objects that are instances of the same class will get their Hot Variable values from the same file, therefore every instance of the same class will share the same Hot Variable values</li>
</ul>

To completely remove these two issues, simply set <code>isJHotReloadActive</code> to false. 
When this property is set to false, <code>HotVariable.of()</code> will return a <code>DisabledHotVariable</code> instead of a <code>HotVariable</code>, Disabled Hot Variables don't lose the values you set in the JSON files, as they read them when they are first instantiated, and then they simply keep using the initial value without ever reading it from the file again, this fixes both problems at once.

This property should ALWAYS be disabled in the final builds of your projects, also consider disabling it when you don't need to use the library during development/testing, as it could cause unexpected behaviours.

<br>

<h4 align="center"><code>crashOnJReadWriteFailure</code></h4>

<br>

<code><i>default value: false</i></code>

When this property is set to true, if a Hot Variable fails to read or write to a JSON file, the program will crash, else it will just print an error message.

When this property is set to true and a Hot Variable fails to read a value, JHotReload throws a <code>JReadException</code>, when it fails to write a value it throws a <code>JWriteException</code>.

When a read/write failure occurs, JHotReload will report that.
See <a href="#errlog"><b>Errors log</b></a>.

<h2 align="center" id="baking">File baking</h2>
JHotReload reads and writes to the JHotReload folder, but when you build your project in a JAR, those files stay outside the final build, so JHotReload regenerates them, and you lose all the values you set for the Hot Variables.

That's why JHotReload can also read from JSON files baked inside the final JAR. You only have to actually include them, for example, in the build.gradle (if you're using Gradle). They must be included in a folder named META-INF/jhotreload/ inside the JAR. 
And don't forget to do the same with the library itself, you need to include JHotReload.jar in your final build.


<h2 align="center" id="errlog">Errors log</h2>
If one or more JHotReload related errors occur during execution, JHotReload will report them in <code>JHotReload\@ErrorLog.log</code>.
